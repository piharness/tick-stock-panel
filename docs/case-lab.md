# 操盘档案（Case Lab）

个人学习页：用**盘后可算的痕迹**去对账**事后才知道的叙事**，把「操盘手法」变成可证伪的判据。

入口 `/case-lab`，四块：结构异常 → 个股解剖 → 案例库 → 判据检验。

---

## 1. 它不做什么

这一页**不**回答「某只票是不是庄股」「某个人是不是在操纵」。它不做三件事：

- 不给个股贴「庄股」标签，也不对任何主体做指控；
- 不从爆料反推事实——爆料可能为真，也可能本身就是出货工具；
- 不自动生成「吸筹 / 拉升 / 派发」的分段。分段是判断，不是观测。

它只回答三个能被检验的问题：

1. 这段结构在历史上出现过多少次？
2. 命中之后 1 / 5 / 20 日，相对**同日同类型**的对照组如何？
3. 我手里的叙事，与本地痕迹对得上吗？

## 2. 三类证据必须分级

| 级别 | 来源 | 可验证性 | 在页面里的位置 |
| --- | --- | --- | --- |
| `official` | 处罚决定书、立案告知、问询函 | 事实权威，但通常滞后 1–3 年 | 案例库（人工录入） |
| `trace` | 日线、龙虎榜、量价结构 | 时点可知、可复现 | 结构异常 / 个股解剖（自动计算） |
| `narrative` | 爆料、媒体报道、研报 | 真假混合、不可核 | 案例库（人工录入，标可信度） |

页面里三者不混在一个列表：痕迹是算出来的，叙事是写进来的，对账是两者相减。

## 3. 判据库（fingerprint）

每条判据 = 语义 + 参数 + 条件 + **反例**。五条内置：

| id | 名称 | 语义 | 关键条件 |
| --- | --- | --- | --- |
| `blowoff_stall` | 天量滞涨 | 放量的钱没换来涨幅 | 成交额创 250 日新高 ∧ 涨幅 < 2% ∧ 收盘在当日下半区 |
| `low_turnover_new_high` | 缩量新高 | 浮筹被锁住 | 收盘创 250 日新高 ∧ 换手 ≤ 250 日 20% 分位 |
| `wash_high_amp` | 高换手对倒（代理） | 成交被放大但方向没定 | 振幅 ≥ 95 分位 ∧ 换手 ≥ 95 分位 ∧ \|涨幅\| < 3% |
| `limit_up_gap_down` | 涨停次日闷杀 | 接力盘被一次性交卸 | 前一日连板 ≥ 1 ∧ 当日跌 ≥ 4% ∧ 量 ≥ 前日 1.5 倍 |
| `upper_shadow_near_high` | 高位长上影 | 上方持续交货 | 上影 ≥ 实体 × 2 ∧ 收盘 ≥ 250 日高 × 0.9 ∧ 换手 ≥ 90 分位 |

三条入库纪律（写在 `backend/app/services/case_lab.py` 的模块注释里）：

1. **无前视**：只用 T 日及之前的数据。参数写进 `params`，展示文本由同一份参数格式化——不给「文档说 2%、代码是 3%」留空间。
2. **先按日聚合再算 t**：同日几十只票共享同一段 beta，不是独立样本；`fwd20` 还在时间上逐日重叠。直接对行算 t 会得到虚高的显著性。
3. **每条判据必须有 `caveat`**：写清它在什么情况下会给出错误印象。

## 4. 统计口径

- **可成交收益**：T+1 开盘买 → T+1 收盘卖。剔除 T+1 开盘涨幅 ≥ 9.8%（一字板买不进）的样本，与 `table_game` 同一阈值。命中总数 `n_raw` 与可买入数 `n_rows` 分列，比值即 `buyable_ratio`。
- **对照组**：同日 × 20 日动量五分位 × 成交额五分位（25 桶/日）。规模用**当时的成交额**而不是最新流通股本——后者含增发、解禁带来的前视。
- **不控制换手率**：多数判据本身用换手定义，再控制它会把要测的效应一起抹掉（over-control）。
- **报告均值 + 中位数 + 胜率**：均值会被少数极端值拉走。实测「涨停次日闷杀」T+20 均值 −227.7bp、中位 −393.9bp——均值掩盖了大多数样本更差的事实。
- **t 只作参考**：同一只票常连续多日命中，日序列自相关，未做 Newey-West 调整。页面显示「命中日数」而不是「独立事件数」。

六年（2026-11 回算，1790 个交易日、845 万行）的实测结果见 `data/case_lab/fingerprint_stats.json`，重算入口：

```bash
cd backend
uv run python -m app.services.case_lab --write   # 重算并落盘
uv run python -m app.services.case_lab --check   # 校验盘上统计与最新数据是否同步（stale 时退出 1）
```

## 5. 候选扫描的排序

`GET /api/case-lab/scan` 按**命中了多少种不同判据**排序，**不看历史收益**。

用全样本收益给当期打分，等于把未来信息放回过去。所以扫描分数只是一个整数：`kinds`。它的用途是「值得打开看一眼」，不是推荐。

## 6. 案例库

一个案例 = 一只票的一段介入周期。存 `data/case_lab/cases/<id>.json`，单文件、原子写、可直接手改。

```jsonc
{
  "id": "c-20261116-ab12",
  "symbol": "002086.SZ",
  "start": "2026-08-17",
  "end": "2026-11-16",
  "actor_type": "unknown",   // hot_money | cap_mgmt | dealer | institution | unknown
  "status": "trace_only",    // penalized | investigated | alleged | trace_only
  "thesis": "一句话论点",
  "evidence": [
    { "date": "2026-11-03", "kind": "penalty|inquiry|filing|leak|media|research|other",
      "source": "决定书文号 / 媒体名", "url": "...", "text": "原文摘录",
      "reliability": "official|media|hearsay|inferred" }
  ],
  "phases":  [{ "label": "吸筹", "start": "...", "end": "...", "note": "..." }],
  "playbook": ["blowoff_stall"],
  "lessons": "下次看到什么，应该警惕什么"
}
```

**对账**（`GET /api/case-lab/cases/{id}/reconcile`）：每条带日期的证据，去 ±N 个交易日里找对应痕迹（判据命中 / 龙虎榜 / 单日 |涨跌| ≥ 7%）。

- `traced` = 那天附近能看到对应结构；
- `untraced` = 本地数据看不到。

`untraced` **不等于叙事为假**。公告全文、大宗交易、股东名册、质押与减持数据都不在这个仓库里——看不到是数据边界，不是事实判断。页面把这句话写在结果下面。

## 7. 数据边界

| 数据 | 覆盖 | 缺失时的行为 |
| --- | --- | --- |
| `kline_daily_enriched` | 2005-01 起 | 区间为空 → `state=no_data` |
| `dragon_tiger` | 2025-11 起（1 日榜） | 更早的区间看不到；3 日榜不混入（累计值不是同一条时间轴） |
| 分钟线 | 仅部分日期落盘 | 日内类判据（尾盘偷袭等）**未入库**——覆盖不足时不假装能算 |
| 公告 / 大宗 / 股东名册 | 无 | 只能人工录入到案例的 `evidence` |

## 8. 已知局限

- 判据是**结构描述**，不是操纵证据。同一形态在消息落地、指数调仓、复牌补跌里也会出现。
- `wash_high_amp` 是**代理变量**：重大消息当天的多空分歧长得很像对倒。
- 五年以上的长区间在 `dissect` 里被截到 600 个交易日——页面画不下那么多根蜡烛，也没有人真的会读完。
- 判据统计窗口取 6 年（2021 起）。再往前（2015 杠杆牛/股灾）交易制度差异过大，混在一起算会把制度变迁算成手法差异。
- 案例的「阶段」由人写，机器不代笔。这是设计选择，不是遗漏。
