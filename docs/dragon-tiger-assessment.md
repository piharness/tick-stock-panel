# 龙虎榜数据接入评估

> 目标：判断「游资真正的痕迹在营业部席位」这条路值不值得做数据接入。
> 方法：先把一年历史回填下来（已做），再用真实的成交口径检验席位跟单有没有可交易超额。
> 结论先说：**数据值得接，但不是用来选股。**

---

## 一、结论

| 用途 | 判定 | 依据 |
|---|---|---|
| 复盘页历史回看 | **值得，已完成** | 已回填 239 个交易日，服务层本地命中、日期正确；修掉了「超一年回退到上一交易日」的错数据路径 |
| 每日增量拉取 | **已接入** | 取数窗口只有一年，缓存永久保留 ⇒ 现在开始积累，三年后就有 700+ 天 |
| 席位跟单策略 | **不做** | 68 个席位逐一检验，最大 t 绝对值只有 2.04（阈值 3.1）；「连续加仓」是负超额 |
| 龙虎榜因子（净买/游资/机构） | **不做** | 全部条件 0 或负；唯一显著的负信号被现有换手率因子完整复现 |

一句话：**龙虎榜里没有信息是换手率给不了的，但它作为「历史上某天资金在做什么」的存档有独立价值。**

## 二、取数可行性（硬约束）

| 项 | 实测值 |
|---|---|
| 历史窗口 | **只有一年**。更早日期返回 `code=1003: date must be within one year` |
| 可用交易日 | 239 天（2025-11-12 ~ 2026-11-06） |
| 本地日K总天数 | 367 天（2025-05-07 ~ 2026-11-06），覆盖率 **65%** |
| 单日三榜耗时 | 中位约 300ms（`all` + `org` + `hot_money` 各一次） |
| 全量回填 | 238 天 / **73 秒** / 306ms 每天，0 失败 |
| 存储 | 21MB / 239 个 JSON（约 88KB 每天） |
| 全量读入 | 239 个 JSON 共 18631 行，**0.27 秒** |
| 数据丢弃 | `stock_count` 合计 27969，实际入库少 18 条（**0.06%**，可转债/B股/退市整理） |

### 关键的窗口性质

一年是**取数限制**，不是**持有上限**。`services.dragon_tiger` 是「历史日读缓存优先」的在线路径，缓存文件一旦写下就不会失效。所以：

- 今天回填的 2025-11-12 数据，明年此时接口已经取不到，但本地文件还在。
- 只要每天有增量拉取，一年后本地就有约 480 天，三年后约 720 天。
- **不接增量，三年后仍然只有现在这 239 天**（而且再往后连这 239 天都补不回来）。

这是本次评估里唯一「有时间价值、且错过不可逆」的部分。

## 三、信号检验

口径统一为：**T 日盘后榜单 → T+1 开盘买入**（A 股 T+1 制度下最早 T+2 才能卖）。
收益 = `open[T+1] → close[T+1+H]`，超额 = 减去同日全市场等权均值。
**所有 t 值都由「按交易日聚合后的序列」算出**，不是按笔。

样本：1 日榜（`range_days=1`）12847 条个股榜，11505 条席位行，68 个游资席位，239 个交易日。

### 3.1 榜单全体就是负超额

| 持有期 | 超额 | t |
|---|---|---|
| H1 | -2.8bp | -0.20 |
| H2 | -45.1bp | -2.61 |
| H5 | **-141.9bp** | **-5.69** |

上了龙虎榜的股票，次日开盘买入后系统性跑输，而且持有越久越差。这与之前审计的"追涨族"结论同向。

### 3.2 但方向类条件全部无效

| 条件 | H1 | H2 | H5 |
|---|---|---|---|
| 净买入 > 0 | +7.0 (0.46) | -20.0 (-1.02) | -122.6 (-4.12) |
| 净卖出 < 0 | -7.8 (-0.42) | — | — |
| 游资净买 > 0 | -1.7 (-0.11) | -38.6 (-1.97) | -124.9 (-4.31) |
| 机构净买 > 0 | +9.5 (0.49) | -21.7 (-0.91) | -139.4 (-4.08) |

括号内为 t。**没有一个方向条件把 -45bp 拉回正数**，最好的"净买入>0"也只是从 -45 缓到 -20。

净买率（`net_rate`）四分位同样没有单调性：-24.7 / +9.0 / +6.8 / +6.7bp —— 只有最差档明显负，其余三档挤在 0 附近且不显著。

### 3.3 席位跟单：68 个席位逐一检验，无一通过

按席位单独统计（只列出现 ≥30 日的 29 个），极值：

| 席位 | 超额 | t | 笔数 |
|---|---|---|---|
| 孙哥 | -280.0bp | -2.04 | 41 |
| 山东帮 | -141.0bp | -1.93 | 135 |
| 宁波桑田路 | -92.8bp | -1.50 | 233 |
| 炒股养家 | -81.7bp | -1.55 | 338 |
| 中山东路 | +72.6bp | +1.35 | 313 |
| 低位挖掘 | +79.6bp | +1.32 | 381 |
| 敢死队 | +175.9bp | +1.04 | 76 |

29 个席位 × 1 个持有期 = 29 次检验，Bonferroni 阈值 |t|≈3.1。最大绝对值 2.04，**没有一条通过**。而且正负号两边都有知名席位，排序效应大概率是噪声。

### 3.4 「连续加仓」是反指

同席位同股连续两日净买入：

| 条件 | H1 超额 | t | 笔数 |
|---|---|---|---|
| 无连续加仓 | +1.7bp | 0.12 | 10510 |
| 连续加仓 ≥1 | **-115.0bp** | **-2.21** | 399 |
| 连续加仓 + 席位 ≥2000万 | **-237.6bp** | **-2.52** | 112 |

游资越加越跌。这符合"连续加仓 = 正在派发/接力盘已经接满"的直觉，但它是对游资信仰的直接反例。

### 3.5 唯一为正的两个子样本，都撑不住

**(a) 席位单笔净买 ≥5000万**：+49.8bp，t=1.34。
分半段：前半 +73.4（t=1.67）/ 后半 +23.4（t=0.38）。
剔除最好的 5 个交易日后只剩 **+10.1bp**。→ 少数几天驱动，不成立。

**(b) 20cm 涨停（创业板/科创板）**：+65.0bp，t=2.28。
分半段（可买样本）：前半 **-3.3bp**（t=-0.09）/ 后半 **+93.9bp**（t=2.14）。→ 全部来自后半段，典型的样本期风格。

另外，10cm 涨停是 **-6.2bp**。之前那轮报的"涨停族 +72bp"，其实是 20cm 独占，10cm 是负的 —— 这是"段怎么切就是定义"的又一个实例。

## 四、决定性的一步：同涨幅对照

上榜股全是当日异动股，直接比较「上榜 vs 全市场」等于在比「异动 vs 不动」。必须按涨幅分箱、同日配对。

下表是**上榜股 减 同涨幅未上榜股**（T+1 开盘可买，剔除 T+1 开盘已涨停的）：

| 涨幅箱 | H1 | H2 | H5 |
|---|---|---|---|
| 10cm 涨停 | +16.4 (0.92) | -2.5 (-0.11) | -74.9 (-2.62) |
| 10cm 涨 5~9.5% | -11.6 (-0.31) | **-116.8 (-2.33)** | **-266.4 (-3.65)** |
| 10cm 涨 2~5% | -37.3 (-0.93) | -98.5 (-1.96) | **-169.5 (-2.57)** |
| 20cm 涨停 | +42.2 (0.55) | +83.5 (0.91) | +47.0 (0.37) |
| **10cm 平盘（-5%~+2%）** | **-82.0 (-2.56)** | **-159.2 (-3.97)** | **-291.1 (-5.08)** |

最后一行是全部实验里唯一 |t|>3 的结果：**当日不涨不跌、却上了龙虎榜的股票，次日开盘买入后 5 日跑输同涨幅股票 291bp。**

这个方向很稳：
- 分半段：H2 前 -116.3 / 后 -190.3；H5 前 -205.9 / 后 -354.3，**两段同号，后段更强**
- 月度：H2 有 10/12 个月为负，H5 有 8/12 个月为负
- 容量：每天只有 **4.3 只**（1~12）

### 但这个信号不是龙虎榜的

上榜股换手率中位 **27.5%**，未上榜 **1.6%** —— 上榜本身就是「换手率极高」的代理（龙虎榜的披露门槛含换手率异常，常见阈值 20%）。所以要问：扣掉换手率还剩什么？

**换手率最邻近匹配**（同日内找换手率相差 ≤3 个点的未上榜股配对，611 对）：

| 持有期 | 差 | t |
|---|---|---|
| H2 | -153.8bp | -2.82 |
| H5 | -85.6bp | **-0.97** |

H5 的 291bp 塌到 86bp 且不显著 ⇒ 长周期超额基本全是换手率。

**更直接的对照：完全不用龙虎榜，只用系统里已有的 `turnover_rate`**

| 条件 | H2 | H5 |
|---|---|---|
| 换手 ≥ 20% | -72.7 (-2.62) | -183.4 (-4.57) |
| 换手 ≥ 25% | -123.6 (-2.94) | **-259.3 (-4.60)** |
| 换手 top 0.1%（阈值 27.7%） | -136.4 (-2.76) | -254.7 (-3.79) |
| 龙虎榜上榜（参照） | -159.2 (-3.97) | -291.1 (-5.08) |

**换手 ≥25% 就复现了上榜股八到九成的负超额，而且样本量大得多（1093 笔 vs 1009 笔，日均 4.2 只 vs 4.3 只）、不需要额外数据源。**

结论：龙虎榜在这个方向上的信息，**已被 `turnover_rate` 完全包含**。要这个效应，扫一遍换手率就够。

## 五、数据本身的缺口

| 缺口 | 影响 | 能否补 |
|---|---|---|
| 只能回溯一年 | 无法做跨年稳健性；本报告所有结论只覆盖 2025-11 ~ 2026-11 | 不能；只能靠每日增量慢慢攒 |
| 无营业部明细（只有"活跃游资"聚合席位） | 无法统计"某营业部席位的胜率"，只能统计平台给的 68 个标签席位 | 需其他数据源 |
| 席位标签是平台的分类，无映射表 | "T王"对应哪些实际营业部未知，无法验证分类稳定性 | 需其他数据源 |
| 无买入/卖出对应关系 | `hot_money_item_net_value` 是净额，看不出是"当日买次日卖"还是"多日建仓" | 不能 |
| 可转债无代码规则 | 每日 1~3 条转债被丢弃（占总行数 0.06%） | 能，加 110/113/123/127/128 前缀规则 |
| 本地日K是存活快照 | 上榜后退市的股票本地无价格；本报告 12847 条中 548 条（4.3%）无价格被剔除 ⇒ 负超额是**保守估计** | 需 PIT 名单 |

## 六、交付物

### 已完成

1. **历史回填**：`data/dragon_tiger/` 从 1 天 → **239 天**（2025-11-12 ~ 2026-11-06），21MB。
2. **回填工具**：`backend/scripts/backfill_dragon_tiger.py`
   - 写出的文件格式与 `services.dragon_tiger` 缓存完全一致，**服务层零改动**即可读回
   - 支持 `--since / --until / --force / --dry-run / --pause`，可重复执行（已有日自动跳过）
   - 校验 `trade_date` 与请求日一致才落盘，避免服务端挪日期污染语义
3. **验收**：`get_dragon_tiger(data_dir, 2026-03-16)` 返回 `state=ok / 58 只 / 19 席位`；`2025-12-01` 返回 `ok / 59 只 / 16 席位`。都是本地读缓存，不发请求。
4. **每日增量**：`services.dragon_tiger.pull_latest()` + 调度 job（19:10 / 20:40，工作日），
   测试 `backend/tests/test_dragon_tiger_daily_pull.py`（12 条）。详见本节末。

### 顺手查清的一个设计后果

回填前 239 天里只有 1 天有缓存，不是偶然。`get_dragon_tiger` 的落盘条件是 `actual < today` —— 而每日盘后复盘调的就是「今天」，所以**在线路径每天都不会写缓存**。缓存只有在用户点开一份 `as_of` 为过去日期的历史复盘报告时才产生，一次一份。

后果有两个：
- 历史长度取决于「用户点过哪些历史报告」，而不是取决于系统跑了多少天；
- 超过一年的历史报告，点开时缓存为空 → 显式日期取数 → `code=1003` → 回退到**上一交易日**并标 `fallback_prev` ⇒ **显示的是错日期的榜单**，而前端只把这个状态当降级提示，不拦。

回填把这两条都堵上了：现在是本地命中，日期正确。

（注：复盘页没有日期选择器 —— `asOf` 硬编码为 `undefined`。所以能看到的龙虎榜只有「今天」和「历史复盘报告列表里点开的那天」，不是任意交易日。）

### 每日增量（已接入调度）

理由见第二节：窗口只有一年，缓存永久保留，不接就永远补不回来。现已落地：

- **时点**：工作日 **19:10** 主跑、**20:40** 幂等补跑（披露通常在 18:00 之后，盘后管道 15:35 太早）。
- **判据是 `is_expected_day`，不是 `state`**：服务端未发布目标日时会安静地返回上一交易日，`state` 依然是 `ok`。只看 `state` 就会得到「每天绿、每天没写今天」——正是原先 239 天只有 1 天缓存的那种假成功。未等到目标日时记 WARNING，把「今天缺了」暴露出来。
- **必须显式落盘**：新增 `services.dragon_tiger.pull_latest()`，不能复用 `get_dragon_tiger`（其落盘条件 `actual < today` 决定它拉「今天」永不写缓存）。
- **两个时点都幂等**：当日缓存已存在直接跳过；休市日（`is_trading_day()` 为 False）直接跳过，不空打接口、不留假告警。
- **失败不阻断**：整个 job 包在 `except Exception` 里，只记日志；缓存写失败单独报 `store_failed`，不吞成 `ok`。
- 成本：每天 3 次 API 调用（两个时点最多 6 次）。
- 回补仍由 `backfill_dragon_tiger.py` 负责。

**如果只想要"回避上榜股"这条规则**：不用接龙虎榜，在因子筛选里加 `turnover_rate` 上限更快、更稳、样本更大。

## 八、与上一轮游资审计的关系

`docs/youzi-strategy-audit.md` 的结论是「淘股吧打法在本地数据上无正超额」，当时留了一个未验证的口子：**游资真正的痕迹在席位，不在形态**。

本报告把这个口子关掉了：
- 席位跟单：0 或负
- 连续加仓：负
- 席位单笔大额：少数几天驱动，剔 5 天后归零
- 唯一的负向信号：已被换手率包含

所以"缺的是龙虎榜历史"这个判断，**对了一半**：数据确实缺，但补上之后并没有新的可交易信息。真正还缺的是**更长的日K + PIT 名单**（决定能不能排除样本期风格），以及**分钟级/竞价数据**（决定能不能表达"9:25 竞价买入"）。这两条都不是龙虎榜能解决的。
