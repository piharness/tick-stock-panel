# 状态变量族批量筛查：预注册

> 写于任何候选的增量被计算之前。上一轮的教训：单假设单报告会让第 64 个候选看起来像发现。
> 本文把**候选如何生成、怎么筛、怎么算多重检验**全部固定，跑完只能照表读。

## 1. 为什么要批量

`osfe-result.md` 的结论是：OS 对 7 个协变量正交化后归零、FE 只是低换手。
如果这个机制是普遍的，那么「技术状态 → 拉升」整族都该归零。逐个验要付 32 次
报告成本；批量验只要一次，且能给出**族级**结论（"这一类没有信息"比"这个没有信息"值钱）。

## 2. 候选的生成规则（不是手挑）

候选 = 日频量价可算、**PIT 无未来**、且属于"状态"（连续或计数，非事件触发）的变量。
按下表**穷举**，不因结果增减：

| 组 | 候选 |
|---|---|
| 位置 | `r5` `r20` `r60` `r250` `dist_ma20` `dist_ma60` `dist_ma120` `dist_ma250` `dist_hi60` `dist_hi250` `dist_lo250` `pos_range250` |
| 波动/形状 | `amp20` `amp60` `vol20` `skew20` `body20` `gap20` `updn_vol20` `updays20` |
| 量能 | `to5` `to20` `to60` `to_trend` `turnover_cv20` `amt_share20` `n_bigup60` |
| 筹码（换手衰减模型） | `os` `os20` `fe` `fe20` `profit` `near_mass` `cost_gap` |

共 **32 个**。每个都检验**两个尾**（Q5 与 Q1），共 **64 个检验**。
不允许"因为方向不对就换尾重报"——两尾都在表里。

## 3. 统一流程（每个候选一模一样）

1. 同日横截面五分位；处理组 = 某一尾的 Q5（或 Q1）。
2. 对照 = 同日 × 同行业内，6 维标准化特征（`log_mcap, r20, r60, to20, amp20, dist_hi250`）
   最近 3 只孪生。**邻居图只算一次，全族共用**——保证 64 个检验的对照口径完全一致，
   避免"换个匹配就跑出个正数"。
3. Δ = 处理组 − 孪生均值（`pump30`，基准 19.06%），按日块自助（L = 12 日，2,000 次）。
4. **正交化闸门（主）**：候选对 7 个核心变量（`profit, amp20, to20, log_mcap, r20, r60,
   dist_hi250`，**剔除候选自身**）做逐日 OLS 取残差，再取残差五分位重复第 1–3 步。
5. 容量：按 ADV20 五分位，看 top-3 档（Q3–Q5 合并）的 Δ。
6. 稳定性：2016–2021 / 2022–2026 分段。
7. 多重检验：族内 100 次同日内标签置换，取**每次置换的族内最大 Δ**构成 max-t 零分布；
   同时给 BH q 值。

## 4. 判据（先写死）

一个候选算「存活」必须**同时**满足：

| 闸门 | 阈值 |
|---|---|
| G1 正交化后增量 | `Δ_resid ≥ +1.5pp` 且 95% CI 不含 0 |
| G2 容量 | top-3 ADV 档 `Δ_resid ≥ +1.5pp` |
| G3 稳定 | 设计期与外样本**同号**且均 ≥ 0 |
| G4 族级显著性 | max-t 置换 `p < 0.05` |

只过 G1 不过 G2/G3/G4 的，记为「统计可见、不可执行」或「族内不显著」，不得表述为发现。

## 5. 预期与它的意义

若 0 个存活 ⇒ 结论固定为：**在日频量价 + 换手衰减筹码这一信息集里，"技术状态"对
60 日拉升概率没有超越 {获利盘, 振幅, 换手, 规模, 动量} 的增量**。这条族级结论
关闭的是整条路线，不是单个因子。

若 ≥1 个存活 ⇒ 逐个查它是不是"涨幅/跳空"的重述（`n_bigup60`、`gap20` 这类天生
接近事件而非状态），并在报告中单列。

## 6. 不做什么

- 不做参数搜索（窗口只取 5/20/60/250 这四档，事先写死）。
- 不做组合（族是单变量；`OS×FE` 已在 `osfe-result.md` 验过）。
- 不因为某候选"看起来合理"就放宽闸门。
- 不改标签（`pump30` 为主判据；`fast30`/`pump20` 只在存活者上做敏感性）。
