# 行业 ETF 盘后扫描：把「未被证伪」变成「可被证伪」

> 脚本：`analysis/etf_watch.py` ｜ 读数 API：`GET /api/etf-watch` ｜ 产出：`data/etf_watch/`
> 上游裁决：[`industry-etf-asymmetry.md`](industry-etf-asymmetry.md) §6 规则、§7 预注册判据
> 状态：**记录模式（record-only）** —— 只记录、不下注、不含任何仓位或委托字段

---

## 0. 为什么是「记录器」而不是又一次回测

上游文档把这条线判为**未被证伪**，不是已证实。原因写在 §7：独立事件只有 **51 个 / 26 个独立月 / 2 轮周期（2022、2024）**。
再跑一次回测只会把同两轮行情重新数一遍，t 值一定更好看，信息量一定为零。唯一能推进的动作是**攒新的真实事件**。

所以这个脚本干的是一件很窄的事：

1. 每天收盘后，用与研究段**同一份代码**算出 20 个行业的位置、波动分位、市场状态；
2. 把满足/不满足 §6 规则的原因逐条写下来（可审计，不是只给一个信号）；
3. 把「dd 首次跌进 −35~−50%」记成一条**不可改写**的事件；
4. 事件到期（20 个交易日）后追加一条结算，累计到 3 个事件簇时给出 V1 判定。

它唯一会「说」的东西是：**现在凑到第几个簇、还差几个、上一次的结果是什么**。

## 1. 怎么跑

```bash
# 扫到最新已完成交易日，写快照 + 事件账本（默认行为）
backend/.venv/Scripts/python.exe analysis/etf_watch.py

# 只看不写（先确认判定对不对）
... analysis/etf_watch.py --dry-run

# 复算某个交易日（用于事后核对）
... analysis/etf_watch.py --asof 2026-11-20

# 口径回归：扫描端的行业净值必须逐点等于研究端 nav.parquet
... analysis/etf_watch.py --verify
```

盘后跑一次，约 25 秒（1720 只 ETF 全量加载 10s + 截尾聚合 8s + 判定）。没有网络请求，不依赖容器，纯读本地 parquet。

**幂等**：同一天重跑不会重复记账（事件按 `日期|行业` 去重，且日快照文件已存在时不再改写）。
**只增不改**：`ledger.jsonl` 只追加，结算单独写成 `type=settle` 的行，读时 join —— 任何一次读数都能追到当时的原样。

## 2. 数据来源与「不许假装最新」

| 来源 | 覆盖 | 说明 |
|---|---|---|
| `data/backfill_20261117/etf_daily_full.parquet` | 2015-07 → 2026-11-17 | 主表，1,569,064 行 |
| `data/kline_etf_daily/date=*/part.parquet` | 2025-11-04 → 至今 | 日增量分区，只取比主表更新的日期 |
| `data/backfill_20261117/index_daily_full.parquet` | → 2026-11-17 | 沪深300（市场状态） |
| `data/kline_index_enriched/date=*/part.parquet` | → 至今 | 指数日增量 |

两套来源在同一天上 **close / amount / volume 逐只相等**（1719 只全等等，已核）；合并后按 `(symbol, date)` 去重取增量。

三条防自欺的规则：

- **15:10 之前不算今天**：当日那根 K 线在收盘前不完整，`resolve_asof` 会退回上一交易日。盘后跑不受影响。
- **ETF 与指数不同步要报警**：指数已到 11-20 而 ETF 只到 11-17 时，输出里会有 `lag_sessions` 与 `warnings`，页面直接显示「缺 N 个交易日，先补数据再判定」。
- **行业停更要单独标**：某行业最后一根有效收益距 asof 超过 3 个交易日，该行业不进候选（`stale_days`），否则「没数据」会被当成「横盘」。

## 3. 判定定义（与上游 §6 一一对应）

| 记号 | 条件 | 阈值来源 |
|---|---|---|
| R1 位置 | `dd = 行业净值 / 250 日高点 − 1` ∈ (−50%, −35%] | 检验 1、F1 |
| R2 波动形态 | 20 日已实现波动的 500 日分位 > 66% | 检验 2（唯一区分真假跌的变量） |
| R3 环境 | 市场状态 ≠ 「上行·低波」 | 检验 3、F3 |
| F6 容量 | 同行业取 20 日均额最大的 ETF，其 `amt20` ≥ 5,000 万 | 成交结构、F6 |

**口径唯一产地**：分类词表、前复权、`dd52`、行业净值、市场状态全部 `import` 自 `analysis/_diag_industry_etf_asym.py` —— 也就是跑出 §4/§5 那张表的同一份代码。
扫描端**不复制任何公式**，只换取数路径（backfill + 增量、截尾 620 个交易日）。

`--verify` 是这个承诺的机械检查：

```
全量 nav 对齐：2281 日 × 20 行业，最大差 0.00e+00
2026-11-20 截尾 vs 全量：dd 最大差 9.99e-16，volpct 最大差 0.00e+00
口径回归: PASS
```

注意 `dd` 是**行业净值口径**（同行业 ETF 按成交额加权收益后累乘），与研究段事件研究同源，不是「各 ETF 的 dd52 加权平均」——后者是位置梯度那张表的口径，两者不是同一个数，混用就会出现「同一个跌破 35% 两个答案」。

## 4. 输出长什么样

`data/etf_watch/latest.json`：

```jsonc
{
  "meta":  { "asof": "2026-11-20", "mode": "record-only", "thresholds": {...} },
  "market":{ "state": "下行·低波", "hs300_close": 3954.57, "vol_pct": 0.41, "f3_active": false },
  "counts":{ "industries": 20, "in_band": 8, "signal": 6, "candidate": 6, "clusters_today": 1 },
  "industries": [ { "industry": "电子", "dd": -0.488, "vol_pct": 0.954,
                    "status": "CANDIDATE", "amt20": 7.8e9,
                    "best_symbol": "...", "best_name": "科创半导体ETF华夏",
                    "reasons": [] } ],
  "ledger": { "events": [...], "settles": [...],
              "v1": { "state": "WAITING", "progress": "0/3",
                      "signal_events": 6, "signal_clusters": 1 } }
}
```

`status` 只有五种：`CANDIDATE`（四条全过）、`BLOCKED`（在区间内但有排除项）、`BLOCKED_F1`（深跌 >50%）、`HIGH`（距新高 10% 内）、`NEUTRAL`。
`reasons` 是逐条中文理由（如 `F2 低波阴跌（volpct 63%）`、`F6 成交额 3555 万 < 5,000 万`），不是分数。

`data/etf_watch/daily/YYYY-MM-DD.json` 是**冻结快照**：已存在就不改写（要重算得手工移走），保证「当时看到的就是这个」。

## 5. V1 的落地口径（两处必须说清，否则数字会自欺）

**(1) 数「事件簇」，不数「行业-行」。**
2026-11-20 首跑，20 个行业里有 6 个同时满足 R1+R2。这不是 6 次独立机会，是**一波行情里的 6 个标签**。
研究段 51 个事件只对应 26 个独立月，正是这个坑。所以 V1 的 `progress` 按自然月成簇计数：

```
"signal_events": 6, "signal_clusters": 1, "progress": "0/3"
```

按行计数会把「1 次」显示成「6/3 达成」，这是最容易被自己骗过去的地方。

**(2) p10 在 N=3 上不存在。**
V1 原文要求「至少 2 次 p10 > −8%」。3 个样本估不出 10% 分位，落地为**每簇的 MAE**（持有期内最差收盘浮亏）> −8%，
并在输出里标注 `left_tail_mapping`。这不是放宽，是把不可估的量换成可观测的量，且换法写在判据旁边。

判定状态：`WAITING`（簇不足 3）→ `PASS` / `FAIL`（3 簇后）→ `RETIRED`（3 簇里 2 簇相对 < −10%，无条件退役，不解释）。

## 6. 首跑结果（2026-11-20，记录第 1 簇）

| 项 | 读数 |
|---|---|
| 市场状态 | 下行·低波（沪深300 3954.57，在 60 日线下，波动分位 0.41） |
| 区间内（−50~−35%） | 8 个行业 |
| 高波信号（volpct > 66%） | 6 个：电子 −48.8%、军工 −47.6%、电新 −46.0%、传媒 −44.2%、计算机 −42.0%、机械 −37.4% |
| 四条全过（CANDIDATE） | 6 个（成交额门槛全过；最大的是科创半导体 78 亿、机器人 17 亿、创业板人工智能 9.6 亿） |
| 被排除 | 通信 −57.4%（F1 深跌）；有色 −43.3%（F2 低波 40%）；交运 −39.7%（F2 63% + F6 3,555 万） |
| V1 | WAITING：**已记录 1 簇、已结算 0 簇**（进度 `0/3`）——簇要等 20 个交易日后才结算，故记录进度与结算进度必须分开看 |

**怎么读这一天**：6 个行业同一天跌破高波阈值，说明这是一次市场级别的下跌，不是 6 个行业各自的故事。
按 §6 的仓位规则，这属于「同时最多 5 个行业」的超限情形——记录器不下注，只把这件事记下来。
如果这 6 个在 20 日后全部为正，V1 也只前进 1 格，不是 6 格。

## 7. 运维与退役

- **每天 15:10 后跑一次**（或写进盘后管道）：`etf_watch.py`。失败不影响其他任务；它只写 `data/etf_watch/`。
- **补数据后重跑**：如果当天 ETF 增量没落盘，扫描会停在上一交易日并给 `lag_sessions` 告警；补完数据重跑即可（幂等）。
- **退役条件已写进代码**（V4）：3 簇里 2 簇 20 日相对 < −10% ⇒ `RETIRED`。退役后本页保留读数但标注失效，不再作为可执行规则。
- **不许做的事**：把历史回测的 51 个事件「导入」账本。那样 V1 会在第一天就「达成」，而这 51 个事件正是它要检验的对象。

## 8. 已知限制

1. 账本从**空**开始（2026-11-20 第 1 簇）。3 簇可能要等 1–2 年，这是设计，不是缺陷。
2. 结算用行业净值算，不是真实成交价：真实成交还要加 ETF 点差与当日冲击（6bp 已含，但离场滑点未单独计）。
3. 无 IOPV / 份额数据，折溢价无法进入判定（上游文档最大空白，此处继承）。
4. 分类词表仍是关键词法：新发 ETF 的命名（如「创业板人工智能」）会归入最接近的行业，可能引入少量误分类；`--dry-run` 的 `best_name` 列就是给人眼复核用的。

## 9. 历史回放与信号追踪（2026-11-22）

`analysis/etf_watch_replay.py` 用同一个 `scan` 逐日重算最近 N 个交易日，产出 `data/etf_watch/replay.json`，页面「历史回放」读取。回答三问：单日快照（当时能看到什么）、六只行业信号轨迹（首次触发/连续/退出再进入）、首次触发后 5/10/20 日与 MAE/MFE（盘中极值，事后评价）。

**已经做到 point-in-time 的部分**：F6 载体按当日 `amt20` 选同行业最大 ETF；停更检查只看 `asof` 及以前（回放前视已修）；`_dejump`/`close_adj` 与研究报告同口径，盘中极值 `hi_adj`/`lo_adj` 用同一个复权比折算；规则版本固定。

**MAE/MFE 口径（2026-11-22 升级）**：从「持有期收盘极值」改为「持有期盘中极值」——用日线 `low/high` 按 `close_adj/close` 折成净值单位，窗口从进场日的**次日**算起（进场日盘内低点发生在买入之前，不算回撤）。`mae_close`/`mfe_close` 保留收盘口径，只用于审计两者差多少；`meta.mae_gap` 记录中位差与最差行业，页面直接读它，不写死数字。

为什么不用 5min 数据：日线 `high/low` 已含集合竞价，比 5min 更全；5min 末根本来就缺集合竞价（见 `cost-vs-return.md`）。**故「拿到分钟数据」不是这个升级的前提，日线极值就够了。**

**未消除、必须和结论一起读的部分**：
- 行业分类用当前 `instruments_etf` 名称映射，数据源没有历史名称/行业变更记录 ⇒ 分类前视未消除。要消除需要「基金曾用名/跟踪指数」的历史，或逐日 `instruments_etf` 快照；本地现存快照只有 1 份（`data/etf_watch/daily` 1 天、`_backup/instruments_20261113_1035` 是股票），不足以重构 120 个交易日的分类。拿到后只需把它们接进分类函数的输入，判定规则一行不改。
- ETF 池是当前在市基金，已退市/清盘基金不在 `etf_daily_full` ⇒ 生存偏差未消除。

**回放不是样本外**：它只用于诊断「提前量」，不改变预注册规则，也不能把 120 个交易日的重算当成新样本。收益列是事后评价，绝不回写当时的候选判定。

**持有期限与退出**：120 日回放只有 1 个事件簇，答不了「该拿几天」。全历史 42 事件/16 独立月的测量见 [`holding-and-exit.md`](holding-and-exit.md)（固定 20 日仍是最优，3–5 日没有超额）。
