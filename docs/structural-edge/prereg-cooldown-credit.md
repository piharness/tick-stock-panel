# 预注册：冷却额度按「实际进场」计（cooldown-credit-2026-11-28）

> 状态：**草案 / 未实现**。规格写定于 2026-11-28，账户当前仍按事件日冷却；
> 实现前不得据此下单。裁决日 2027-02-26。
> 触发事件：2026-11-27 电子重新成为候选段首，账户不买 —— 因为 11-04 的段首还在
> 60 日冷却里，而那笔发生在账户启用日（11-20）之前，账户从未持有过。

## 1. 问题：冷却额度与持仓脱钩

冷却是为了防「同一轮下跌重复下注」。`build_events` 把锚点放在**事件日**，
于是额度会在三种「账户没有承担对应风险」的情况下被消耗：

| # | 情形 | 例子 |
|---|---|---|
| 1 | 事件发生在账户启用日之前 | 电子 2026-11-04（启用 -12 个交易日） |
| 2 | 六格已满、资金不足被跳过的信号 | 待核（`trades_closed` 尚为 0，样本不够） |
| 3 | F1 深跌拦截后重新合格 | 电子 11-25/26 破 −50% → 11-27 回 −45.8% |

这三种情形都没有持仓，却都消耗了 60 个交易日的额度。没有下注，就没有重复下注。

## 2. 已经看到的数（诊断，不是证据）

`python analysis/_diag_cooldown_credit.py`（2018-03 → 2026-11-27，42,220 行扫描矩阵）：

- raw 候选段首 **89** 个 → 冷却后 **43** 个，吃掉 **46**（52%）
- 其中距上一段首 **< 20 日**（上一笔还没到期平仓）**29** 个 —— 冷却在这里是对的
- 距上一段首 **≥ 20 日**（上一笔已平仓、额度仍未解锁）**17** 个 —— 上限就是这 17 次机会

启用切口的暴露面（本预注册的主要动机）：

| 行业 | 段首日 | 距启用 | 额度解锁（≈） |
|---|---|---|---|
| 交运 / 传媒 / 军工 / 计算机 | 2026-10-30 | −15 个交易日 | 2027-01-22 |
| 电子 / 电新 / 通信 | 2026-11-04 | −12 个交易日 | 2027-01-27 |

**20 个行业里有 7 个（35%）在账户启用后的头两个月处于冷却盲区**，而这 7 个行业
在启用时全部是零持仓。这不是边界情形，是启用动作本身造出来的。

## 3. 冻结规格（v1，未实现）

**定义**

`credit(ind, t)` = 该行业最近一次**实际进场**（replay 中 `entry` 非空）的交易日。

**放行条件**

```
status[ind, t] == CANDIDATE
且 t − credit(ind) ≥ 60 个交易日
且 该行业当日无持仓
```

- 未进场的事件不消耗额度（资金不足、F1 拦截、启用日之前，一视同仁）。
- 60 这个数**不动**；20 日持有、六格仓位、6bp/边成本都不动。

**落地位置（分层，不改回测口径）**

- `etf_watch_experiments.build_events` 的矩阵层冷却**保留**：它定义「43 个历史事件」，
  是 `holding-and-exit.md` / `portfolio-replay.md` / JB0 的共同样本。改它 = 换策略。
- 账户层在 `etf_watch_account.load_world()` 之后重建一份**账户专属事件集**：
  先用 `build_events` 拿候选段首，再按 `credit` 过滤。
- `seg_first`（页面读的字段）取这份账户事件集，于是「页面可执行」= 「指令买入」。

**为什么不做成可累积余额**：余额需要记「欠了多少额度」，会引入新的状态机；
只记「最近一次进场日」是一个可重放的事实，符合本仓库「无增量状态」的原则。

## 4. 判据（冻结）

评估日 **2027-02-26**（账户启用后满 60 个交易日），或前向满 40 个交易日且已出现
≥1 次「幽灵冷却」事件，以先到者为准。

| 判据 | 阈值 | 类型 |
|---|---|---|
| 实现正确性 | 电子若在 ≈2027-01-27 之前再次成为候选段首，改后必须给出 BUY 指令；改前必然没有 | 硬 |
| 口径一致 | 任一日：账户 BUY 的行业集合 == `seg_first`，且 `seg_first ⊆ 当日 CANDIDATE` | 硬 |
| 回测不变性 | 2019-2026 重放：CAGR 变化 ≤ ±0.3pct，MDD 变化 ≤ ±1.0pct | 硬 |
| 交易频率 | 60 个交易日内新增进场 ≤ 3 笔 | 软 |
| 红线 | 不得出现同行业同时持有两笔 | 硬 |

**通过** → 账户层启用，`account-runbook.md` 改写冷却锚点。
**否决**（任一硬判据不过）→ 撤回，回到按事件日冷却；把这 17 次机会成本记进
`holding-and-exit.md` 的已知偏差，不再尝试修。

「回测不变性」是这份预注册的核心：如果改动让历史 CAGR 动了超过 0.3pct，说明它
不只是修启用切口，而是在改策略性格 —— 那就必须重新走一遍预注册，不能借「修 bug」的名义换参数。

## 5. 不做什么

- 不改 60 这个数（想试 40/90 另写预注册）。
- 不改 `build_events`，不重算 43 个历史事件。
- 不引入额度余额、不引入行业权重。
- 不在本文评估收益 —— 60 个交易日、最多 3 笔，任何读数都没有功效。
