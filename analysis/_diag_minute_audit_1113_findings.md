## 1. 修复后是 rc=3，不是 rc=0

`--repair-phantom --apply` 已执行（备份在 `data/_backup/minute_audit/20261113_081339/`），
逐日重跑：

```
11-05  L 0  M 0   11-06  L 0  M 0   11-09  L 0  M 1  ← 920375.BJ +4,001 手
11-10  L 0  M 0   11-11  L 0  M 0   11-12  L 0  M 0
=> rc=3
```

11-09 那 1 行不是幽灵（这天没有 13:00 行）。它是**日线不含、分钟含**那 4,001 手，
删除幽灵动不到它。上一版只验了 11-05 与 11-12 —— 恰好是两天都归零的那两天。

## 2. 第三轴：286 → 9，剩下 277 根是「整手取整」

`volume` 是整手取整的，所以一笔「只按 close 成交」的 bar 必然满足
`|amount − volume·100·close| ≤ 1 手 × 100 × close`。实测：

| V 区间 | n | max V·\|dev\| | 超 1 手 |
|---|---|---|---|
| [0, 10) | 120 | 0.92 | 0 |
| [10, 30) | 375 | 0.89 | 0 |
| [30, 100) | 2,070 | 0.96 | 0 |
| [100, 1000) | 15,951 | 0.99 | 0 |
| ≥ 1000 | 14,885 | **2,204.80** | **9** |

V<1000 的 18,516 根**没有一根**越 1 手 —— 那 1%~29% 的偏离全部落在取整上界内。
上一版看到的「BJ 占 60%、科创板次之」是**手数分布**的镜像（BJ/科创板小票多），
不是市场结构。

判据因此改成**整手残差**：`> 1 手` 恰好 9 根，下一根在 **40 手**，阈值在 (1,40)
之间取什么都一样。9 根全 BJ、全为负偏离（成交价低于收盘）。

## 3. 「内部恒绿」不成立：日线自身就能否掉一行

`amount/(volume·100)` 必须落在**该行自己的** `[low, high]` 内。6 天 33,430 行里
只有 **6 行**越界，全 BJ；SH/SZ 31,301 行 **0 命中**。

`920717.BJ 11-06`：均价 `6.1666 < low 6.18`，而 `20,580 − 14,152 = 6,428`
正好是 fuyao 的值 —— 这一行不需要外部源就能判死。

三条轴覆盖的是**不同的表**，不是同一张表的不同行：

* **M** 只在两表分歧时响（11-09 一例）；
* **S** 看日线自身（6 例），其中 3 例 fuyao 也含那笔量 ⇒ 外部轴对它们恒绿；
* **E** 看日线与 fuyao（4 例），其中 920112 的成交价落在区间内 ⇒ S 看不见。

单靠任何一条都不够；但**B（收盘 bar 残差）单独就覆盖了全部 9 例**，
因为它直接看分钟侧 —— 这与「S/E 看日线侧」是互补关系，不是冗余。

## 修法（已执行）

1. **备份落点**：`part.bak-<ts>.parquet` 会被 `*.parquet` 命中（审计与
   `decision/bars.py::_day_frame` 都是 glob 后直接 concat）⇒ 修一次、脏两次。
   改到 `data/_backup/minute_audit/<ts>/date=<day>/part.parquet`。
2. **原子写**：原 `write_parquet(src)` 直接覆盖 1.3M 行分区，中途失败留半个文件。
   改为写 `.tmp` 再 `os.replace`。
3. **读侧守卫**：`_minute_frame` 读取时断言 `(symbol, datetime)` 唯一，重复即抛。
   负控：往分区塞一个键重叠的 `part-stream-0.parquet` ⇒ 当场 `RuntimeError`。
4. **默认窗口**：`DEFAULT_DAYS` 硬编码 6 天 ⇒ 明天跑还是这一周。改 `latest_days()`。
5. **退出码**：`0` 全绿 / `2` 仅标注 / `3` 金额量差异 / **`4` 有非竞价成交**。
   3 优先于 4。之前 B、S 只打印、不进 rc，等于「看得见但不影响判定」。

## 仍未闭合

1. **13:00 成因未定位**，且 `_write_minute_partition` 没有任何针对 13:00 的防护
   ⇒ 幽灵行**会复发**（本批 11-05/11-12 两天，间隔三天）。修复是清账不是治病，
   判据必须在每天重跑时能再抓住它（现在能）。
2. **北交所口径是决策，不是 bug**。更麻烦的是**无法回溯修复**：两表都含那笔量时，
   账上只有「总量」一个数，分离它需要的第二个数并不存在。
   建议打标（`vol_basis = auction_only | incl_block | unknown`）而不是假装修好；
   下游（换手率、量比、均价）按标决定用不用。
3. **4 行日线错仍在**，其中 3 行 fuyao 也含那笔量 ⇒ **换源解决不了**，只能靠 S 轴拦。
4. `analysis/` 没有进 provenance registry，本文件的数字会让那项检查继续红
   （既有债，非本轮引入，但本轮加了行数）。
