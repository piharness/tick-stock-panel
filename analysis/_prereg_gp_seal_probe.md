## 0. 这一次调用买什么

只买两件事：

- (a) 账户对 GP 封板字段**有没有权限**；
- (b) 拿到的列**是不是文档说的那个量**（权限 ≠ 语义）。

**不买开研究线的授权。** PASS 之后要另立一步，按 `触发率 × 单次效应 × 242 − 成本` 立项，并先估算
2018–2025 全量拉取成本。理由：本次探针只能否决，不能授权——「有数据」不蕴含「效应够大」。

## 1. 判定的对象

**4 个 `get_pro_data(type=3)` 请求**（每票一个，字段批量放进 `table_list`），不是一次批量调用：

- `fields` = `GP14 GP15 GP22 GP24`
- 窗口 = **单日 2025-11-13**（与本地 `data/dragon_tiger/date=2025-11-13.json` 同日，可交叉核对）
- `symbols` = 2 正控 + 2 负控（§2），沪深优先，上限 6

调用层写死（§6 有取证过程）：`_NativeTdxAiData.get_instance().get_pro_data(json)`，
payload 复刻 `tqs._pro` 的 `type=3` 形状，`start_time/end_time` 走 `tqs._time`。
**不得走 `client._raw("get_gpjy_value", ...)`** —— 原生层没有这个方法（见 §6）。

字段语义按装机 1.2.2 自带文档 `tdxaidata使用文档.md:2022-2032`：

| 字段 | 内容 | 覆盖 |
|---|---|---|
| GP14 | 涨停金额(万元) + 开板次数 | 20180319+ |
| GP15 | 涨跌停状态(2涨停/1曾涨停/-2跌停/-1曾跌停) + **封单金额(万元，跌停取负)** | 20160926+ |
| GP22 | **封成比 + 封流比** | 20180319+ |
| GP24 | 首次涨停时间 + 涨停最大封单额(万) | 时间 20160301+，金额 20200730+ |

⇒ 真正的封单在 **GP15 / GP24**；`GP14` 是「涨停金额」不是「封单」，不得用它当封板强度。
⇒ `GP22` 的封成比 / 封流比**自带归一化**（÷成交额、÷流通市值），是打板横截面该用的量，省掉自算流通股本。

## 2. 对照选取（口径写死，跑完不许换）

源：`data/dragon_tiger/date=2025-11-13.json` 的 `all.stock_items`。**先按 ticker 去重**（当日 70 条 / 唯一 64 条，6 只重复上榜）。

- 达板阈值**按板块**：主板(60/00) ≥9.9%、创业板(30)/科创(68) ≥19.9%、北交(43/83/87/88/92) ≥29.9%；名称含 `ST` 的一律排除；
  北交标的**两边都不用**（探针目标是沪深，混进 `.BJ` 会让 F1/F2 的归因变脏）。
  当日口径下：all 榜 70 行 / 唯一 64 只，**达板 29 只**，`|change| < 2%` 的 5 只。
- 正控：达板票按 `change` 降序取前 2 = `300497 富祥药业 20.03%`、`688602 康鹏科技 20.02%`。
- 负控：`|change| < 2%` 且非 ST、非北交，按 `|change|` 升序取 2 = `600506 统一股份 -0.10%`、`001298 好上好 +1.39%`。

两条必须写死的理由（否则负控会变成正控）：

1. `change` 是**小数**不是百分数（当日 max=`0.299661`）。写 `>= 9.8` 命中 0 条。
2. 不能用 `< 5%` 选负控：ST 票 5% 即涨停，当日 `*ST东易 4.99`、`ST景峰 4.99` 会被选成「非涨停」。

## 3. PASS 条件（三条全中）

- **P1 权限**：4 只票都返回非空；GP15 状态在正控上 ∈{2,1}，在负控上 ∉{2,1} 或封单金额为 0/空。
- **P2 语义**：正控上 `GP15封单金额(万)×1e4 ÷ 当日成交额` 与 `GP22封成比` 相对误差 < **20%**，且 ≥2 只成立。
  成交额取 `data/kline_daily` 当日 `amount`；某只取不到则该只不计入，P2 仍需 ≥2 只成立。
  **量纲先定，再算误差**：`封成比` 落在 `[1, 100]` 视作百分数（先 ÷100），否则视作小数；择一后同一轮不得切换，
  所择量纲写进判定 JSON。*理由：不同源的封成比既可能是 0.02 也可能是 2.0，不先定量纲就会出现差 100 倍的
  假 F3，一次就烧掉 §4 允许的唯一重试。*
  *20% 是设计选择不是实测。若首跑落在 20%–50%，**不得就地放宽**：按 F3 记录口径差异（封单额可能含集合竞价、封成比可能用最大封单），换 id 重注册。*
- **P3 覆盖**：返回的 `date_range` 覆盖 2025-11-13。

## 4. FAIL 五类，各自对应什么结论

- **F0 调用层不可用**（方法不存在 / 导入失败 / DLL 未就绪 / 参数签名不符）→ **不是无权限，不得关线**。
  先修探针再谈数据。典型原文含 `has no attribute`、`ImportError`、`OSError`。
  *这条是本条协议最贵的一格：把 F0 读成 F1 会永久关掉一条只是"还没打开"的线。*
- **F1 全空** + 错误原文含权限/套餐/未开通字样 → 真无权限。**研究线关闭**，留档，不再重探。
- **F2 非空但负控也拿到非零封单或状态∈{2,1}** → 字段不是封单（例如把状态位当成了封单）。**研究线关闭**。
- **F3 形状与文档不符**（列名/顺序/日期粒度不对）→ 参数或版本问题，可原地重试**一次**，`attempt` 记 2；
  **仍失败按 F0 处理（换路径或挂起），不得按 F1 关线。**
- **F4 空返回且无任何错误原文** → **不可归因**：分不清"无覆盖期""参数被静默丢弃""确实当日无数据"。
  不得读成无权限。动作：换一个窗口（例如往前推 20 个交易日）重试一次，仍空则按 F0 挂起。

F1/F2 关闭研究线时，结论写作「未检验且不可得」，不得写成「已证伪」。F0/F4 一律**不产生结论**，只产生下一个动作。
